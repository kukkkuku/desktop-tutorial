### 1.3 가져올 때 반드시 처리할 함정

1. **병합 셀.** H/L1/L2는 세로로 병합돼 있어서 API로 읽으면 첫 행에만 값이 있다.
   → 병합 범위를 읽어 아래로 채운다.
2. **병합이 끊긴 행.** "SW 제품 디자인 개선" 6행, "런칭 지원 디자인 개발" 13행은
   H/L1이 비어 있다. → 바로 위 행의 H/L1을 이어받고, 미리보기에 "추정" 표시를 한다.
3. **연도마다 다른 컬럼 구성.** 2025 탭은 앞쪽에 `분류/구분/등급`이 끼어 있고,
   H 헤더가 오타 `ㅗ`로 되어 있다.
   → 열 위치를 고정하지 말고 **헤더 이름으로 찾는다.** 못 찾은 열은 사용자에게
   수동 지정을 받는다.
4. **한 달의 주 수가 4주 또는 5주.** 1·4·7·10월은 5주다.
   일정표 빌더는 한 달을 4주로 고정하므로 그대로 쓰면 틀린다.
   → 주차 축은 **시트 헤더를 그대로** 읽는다.
5. **담당자 표기가 제각각.** `/`, `, `, 줄바꿈으로 구분되고, `"방인용\n국내"`처럼
   이름이 아닌 값이 섞여 있다.
   → 쪼갠 뒤 팀원 목록과 대조한다. 목록에 없는 이름은 "새 팀원 후보"와
   "무시" 중에서 고르게 한다.
6. **오타 값.** `OnePlatformt팀`, `내무` 등.
   → 가져오기 미리보기에서 경고만 하고 **자동으로 고치지 않는다.**
   원본 값을 지어내지 않는다는 원칙 때문이다.
7. **`[중점]` 태그.** L2 이름 안에 들어 있다. → L2의 `tag` 필드로 분리한다.
   L3의 과제등급으로 **자동 변환하지 않는다.** 과제등급은 시트의 `분류` 열(과제/일반/일상)에서 온다(6.2).

## 2. 메뉴 구성

```
[팀/기간 ▾]  과제관리 | 팀원관리 | 평가하기 | 평가결과 | 팀원 면담      [데이터 관리] [계정]
```

| 메뉴 | 바뀌는 점 |
|---|---|
| **과제관리** (기존 탭 교체) | 위쪽에 L2 탭 줄, 아래에 L3 편집 표. 보기 전환: **표 / 일정** |
| **팀원관리** | 기존 기능 유지. "시트에서 가져오기" 추가. 팀원에 `email`·`team` 필드 추가 |
| **데이터 관리** (기존 드로어 → 전체 화면) | 서브탭: **구글시트 연결**(신규) · 내보내기 · 백업/Drive · 권한·초대 · 초기화 |
| 평가하기 | 앞 단계로 **평가 과제 만들기**(L3 하나 또는 묶음, 6.1)를 추가한다. 업무량 열은 숨긴다 |
| 평가결과 / 면담 | 과제등급 표시만 3단계로 바꾼다 |

기존 헤더의 "데이터 관리" 드로어와 이름이 겹친다. 드로어의 내용을 새 화면의
서브탭으로 흡수해 **하나로 합친다.**

### 2.1 과제관리 화면

```
┌ L2 탭 (일정표 빌더의 폴더 탭 모양) ──────────────────────────────────────────┐
│ [중국시장 중심…[중점]] [글로벌 성장…] [해외 브랜드디자인…] [＋ L2]  시트:12분 전 ⟳│
├──────────────────────────────────────────────────────────────────────────────┤
│ H 브랜드 디자인W › L1 브랜드 디자인 연구 · 출처: 시트 · L3 45건 · 진행 18/완료 27 │
│ [표 | 일정]  🔍검색  담당자▾ 상태▾ 속성▾   ↶ ↷   열 표시▾   엑셀 내보내기        │
├──┬───────────────────────────┬──────┬───────┬──────┬─────────┬──────┬──────┬─────┤
│⋮⋮│ L3 과제명                  │ 속성 │ 분류  │ 상태 │ 담당자  │ 담당팀│완료요청│ ＋  │
│⋮⋮│ (중국법인) 위챗 채널 영상… │ 브랜드│ 과제  │진행중│ 조은총  │ 해외…│ 01-31 │     │
│⋮⋮│ …                         │      │       │      │조은총,구도이│   │       │     │
└──┴───────────────────────────┴──────┴───────┴──────┴─────────┴──────┴──────┴─────┘
  ＋ L3 추가
```

- **L2 탭**
  - 탭을 우클릭하면: 이름 바꾸기, 복제, 좌우 이동, 삭제, "시트와 다시 맞추기"
  - 탭은 드래그로 순서를 바꾼다.
  - 탭에 출처 배지(`시트` / `직접`)를 붙인다.
- **일정 보기**
  - 같은 L3 행에 주차 격자를 붙여 보여 준다. 칸 값은 `S`(시작) / `완`·`F`(완료).
  - 칸을 클릭하면 값이 `빈칸 → S → 완 → 빈칸` 순으로 바뀐다. 앱에서 찍는 완료는 `완`으로 통일한다.
  - 시트에서 온 `F`는 원문 그대로 보존한다(다시 내보내도 바뀌지 않게). 화면·집계에서는 `완`과 똑같이 완료로 취급한다.
  - 드래그하면 여러 칸에 같은 값을 넣는다.
  - 오늘선(빨간 점선)과 완료요청일 ▲ 마커를 표시한다.

## 3. 데이터 관리 › 구글시트 연결 (가져오기 흐름)

```
① 링크 붙여넣기 → ② 탭 선택 → ③ 열 매핑 확인 → ④ L2 고르기 → ⑤ 미리보기·정리 → ⑥ 가져오기
```

1. **링크 붙여넣기**
   - URL에서 `spreadsheetId`와 `gid`를 뽑는다. gid가 있으면 그 탭을 먼저 선택해 둔다.
   - 연결 정보(시트 id, 탭 이름)는 워크스페이스에 저장해서 다음부터는 "⟳ 다시 가져오기" 한 번으로 끝낸다.
2. **탭 선택**
   - 시트의 탭 목록을 보여 준다. 숨김 탭은 흐리게 표시한다.
   - 기본 선택: 평가연도와 같은 `YYYY 추진현황` 탭.
3. **열 매핑**
   - H/L1/L2/L3, 담당자, 상태 등을 **헤더 이름으로 자동 매칭**한다.
   - 못 찾은 열만 드롭다운으로 받는다.
   - 매칭 결과는 탭별로 기억한다.
4. **L2 고르기** (이 화면의 핵심 목적)
   ```
   ☐ 브랜드 디자인W
      ☐ 브랜드 디자인 연구
         ☑ 중국시장 중심 디자인 경쟁력강화 [중점]   L3 45 · 해외브랜드 40 / 국내 5
         ☐ 글로벌 성장 전략 기반 …                  L3  8
   ```
   - 트리 구조: H › L1 › L2. 상위를 체크하면 하위가 모두 체크된다.
   - 각 L2에 L3 건수와 **담당팀별 건수**를 보여 준다.
   - 빠른 선택: **"우리 팀 담당 L3가 있는 L2만"** (팀명 ↔ 담당팀 매칭)
   - 선택 옵션: "선택한 L2 안에서도 우리 팀 담당 L3만 가져오기"
5. **미리보기·정리**
   - 가져올 L3 표를 보여 준다.
   - 경고 목록: 추정한 H/L1, 팀원 목록에 없는 담당자, 오타 의심 값, 필수값(L3명) 누락
   - 목록에 없는 담당자는 각각 `새 팀원으로 추가` / `무시` 중에서 고른다.
6. **가져오기 (다시 가져오기 포함)**
   - 행을 맞추는 키는 **`L2 이름 + L3 이름`**이다. 시트 행 번호는 행 삽입 때문에 바뀌므로 쓰지 않는다.
   - 앱에서 고친 적 없는 필드는 시트 값으로 갱신한다.
   - **앱에서 고친 필드**는 "시트 값 / 앱 값" 비교를 보여 주고 사용자가 고른다.
     필드별 `editedAt`으로 앱에서 고쳤는지 판단한다.
   - 시트에서 사라진 L3는 **삭제하지 않고** "시트에 없음" 배지를 붙인다.
   - 새로 생긴 L3는 추가한다.

### 3.1 시트를 읽는 방법

| 방법 | 장점 | 단점 | 채택 |
|---|---|---|---|
| **A. Sheets API v4 + 로그인 계정 권한** (`spreadsheets.readonly`) | 링크만으로 가능, 최신값, 병합 정보까지 옴 | 스코프 추가(사용자 동의 1회), 회사 Workspace가 외부 앱을 막으면 불가 | **기본** |
| B. 시트 → 파일 › 다운로드 › xlsx → 앱에 업로드 | 권한 문제 없음, 오프라인 가능 | 수동, 최신성은 사용자 몫 | **대체 경로** (같은 파서 사용) |
| C. "웹에 게시" CSV | 로그인 불필요 | 회사 데이터를 공개해야 함 | 사용 안 함 |

- **호출 방식**
  - `spreadsheets.get?fields=sheets(properties,merges)`로 탭 목록과 병합 범위를 가져온다.
  - `values.get(탭!A1:BZ, FORMATTED_VALUE)`로 값을 가져온다.
  - 두 번 호출하면 되고, 행 500개 정도는 1초 안쪽이다.
- **스코프**
  - `spreadsheets.readonly`는 "가져오기"를 처음 누를 때 **추가 동의**로 받는다.
    기존 로그인에는 영향이 없다.
  - 앱이 현재 GCP OAuth "테스트" 모드라서 민감 스코프를 추가해도 등록된
    테스트 사용자는 바로 쓸 수 있다.
- **시트에 되돌려 쓰기**
  - 처음 단계에서는 **만들지 않는다.** 여러 사람이 같이 쓰는 시트라서
    병합 셀·수식·다른 팀 행을 덮어쓸 위험이 크다.
  - 대신 5장의 "시트 양식 엑셀 내보내기"로 팀장이 붙여넣게 한다.
  - 필요하면 4단계에서 L3 행 단위로 범위를 좁혀 쓰는 기능을 검토한다.

## 4. 표 편집기 (일정표 빌더 → React 이식)

일정표 빌더의 **새 격자 모듈(`GS`/`gApply`)**만 이식한다. 옛 선택 로직은 쓰지 않는다.

### 4.1 가져오는 것

| 기능 | 조작 |
|---|---|
| 셀 편집 | 클릭 = 선택(바로 치면 덮어씀), 더블클릭 / Enter / F2 = 편집, Esc 또는 바깥 클릭 = 저장 |
| 범위 선택 | 드래그, Shift+클릭 |
| 행·열 선택 | 왼쪽 행 손잡이 ⋮⋮, 열 머리글 클릭·드래그 |
| 행 추가 | 표 아래 "＋ L3 추가", 행 경계 hover ＋, 우클릭 "위/아래에 추가" |
| 열 추가 | 오른쪽 끝 ＋, 열 경계 hover "＋ 열", 우클릭 "왼/오른쪽에 추가" |
| 삭제 | 행·열 선택 후 Delete. 값이 있는 열은 한 번 확인 |
| 이동 | 손잡이 드래그(빨간 삽입선), ⌘/Alt+↑↓ |
| 이름 바꾸기 | 열 머리글 더블클릭 |
| 열 폭 | 머리글 오른쪽 끝 드래그 (기존 `ResizableTh`와 통합) |
| 되돌리기 | ⌘Z / ⌘⇧Z, 60단계 스냅샷 |
| 컨텍스트 메뉴 | `.pop.menu` 모양 그대로 |
| 선택 표시 | `gsel` inset 2px 파랑, 드래그·드롭은 주황 |

### 4.2 새로 만드는 것 (빌더에 없음)

- 화살표·Tab 키로 셀 이동
- **엑셀/시트에서 붙여넣기(TSV).** 선택한 칸부터 채우고, 모자라면 행을 추가한다.
- 복사(⌘C)
- **열 타입**
  - 텍스트
  - 여러 줄 메모: 진행 메모 열용. 칸에서는 마지막 줄만 보이고 펼치면 전체가 보인다.
  - 선택형(상태·분류·속성·내/외): 선택지는 시트에 있는 값으로 자동 생성
  - 날짜
  - **사람**: 담당자. 팀원 칩으로 여러 명 선택
  - 링크
- 열 머리글 ▾ 메뉴에서 필터·정렬
- 열 표시/숨기기

### 4.3 가져오지 않는 것

- **셀 병합·나누기·칼 도구.** L3 표는 한 행이 과제 하나인 데이터 표다.
  병합은 보고서 모양일 때만 필요하므로 L2 탭 구조가 그 역할을 대신한다.
- 페이지 스타일 6종, PPT 내보내기, 공유 링크. 필요하면 나중에 "보고용 일정표 내보내기"로 검토한다.

### 4.4 열(컬럼) 규칙

- **시스템 열**: 시트와 매핑되는 열(L3명, 담당자, 상태 등)
  - 숨길 수는 있지만 **삭제는 안 된다.** 삭제하면 다음 가져오기 때 다시 생긴다.
  - 이름은 표시 이름만 바꾼다.
- **사용자 열**: 앱에서 추가한 열
  - 추가·삭제·이름 바꾸기가 자유롭다.
  - L2마다 따로가 아니라 **워크스페이스 공통**이다(모든 L2 탭에 같은 열).
    확인 필요: L2마다 다른 열이 필요한지.

## 6. 데이터 모델 (안)

**핵심 결정: L3(업무)와 평가 과제를 분리한다.**
- 평가는 L3 하나로 할 수도 있고, 여러 L3를 묶은 그룹으로 할 수도 있다(2026-09-24 확인).
- 그래서 과제관리의 L3는 `WorkItem`으로 새로 만든다.
- 기존 `Task`는 **평가 과제**로 남기고, 어떤 L3로 이루어졌는지 `workItemIds`로 가리킨다.
- 평가하기·평가결과·기여도·피어리뷰 코드는 계속 `Task`를 읽는다.
  그래서 평가 쪽 변경을 최소로 줄일 수 있다.

```ts
// L2 -- 팀장이 만들거나 시트에서 가져온다
interface TaskGroup {
  id: string
  name: string                 // "[중점]" 태그를 뺀 이름
  tag: string | null           // "중점" 등. 시트에 있던 그대로
  h: string | null             // 원본 H
  l1: string | null            // 원본 L1
  hierarchyInferred?: boolean  // H/L1을 위 행에서 이어받았는지 (1.3의 2번)
  order: number
  source: 'sheet' | 'app'
}

// L3 -- 과제관리 화면의 한 행
interface WorkItem {
  id: string
  groupId: string
  name: string
  source: 'sheet' | 'app'
  sheetKey?: string                      // L2명 + L3명, 다시 가져올 때 매칭용
  category: TaskCategory | null          // 시트 '분류' 열. 과제 / 일반 / 일상. 비었거나 이상한 값이면 null
  categoryRaw?: string                   // 시트 원문 ("완료" 같은 이상값 보존)
  assigneeIds: string[]                  // 팀원 id
  assigneeRaw?: string                   // 시트 원문 "조은총/ 구도이"
  fields: Record<string, string | null>  // 속성·상태·수요부서·담당팀·완료요청… + 사용자 열
  weeks: Record<string, 'S' | '완' | 'F'> // "2026-01-1" → 'S'
  editedAt?: Record<string, string>      // 필드별: 앱에서 고친 시각
  missingInSheet?: boolean
}

type TaskCategory = '과제' | '일반' | '일상'

// 평가 과제 -- 기존 Task를 확장한다
interface Task {
  id: string
  name: string                           // L3 하나면 그 이름, 묶음이면 팀장이 지은 이름
  workItemIds: string[]                  // 1개 = 단일 L3, 2개 이상 = 묶음. 예전 데이터는 []
  importance: TaskCategory | null        // 과제등급 (아래 규칙)
  performanceGrade: PerformanceGrade | null  // 성과등급 -- 팀장만 입력. null = 미입력
  workload: Workload                     // 사용 안 함 (예전 데이터 보존용). 화면에서 숨김
  objective: string
  achievement: string
}

interface ColumnDef {
  id: string
  label: string
  type: 'text' | 'memo' | 'select' | 'date' | 'person' | 'link'
  system: boolean
  sheetHeader?: string
  width?: number
  hidden?: boolean
  options?: string[]
  groupId?: string                        // 없으면 모든 L2 공통 (4.4)
}

interface SheetLink {
  spreadsheetId: string
  tabName: string
  gid?: number
  columnMap: Record<string, string>
  selectedGroups: string[]
  lastFetchedAt?: string
}

interface TeamMember {
  /* 기존 필드 */
  email?: string               // 권한용 (8장)
  team?: string                // 담당팀
}
```

### 6.1 평가 과제 만들기 (평가하기 탭 앞 단계)

(2026-09-24 변경) 팝업 없이 과제관리 표에서 묶고, 정리가 끝나면 체크해서 내보낸다.

```
1) 묶기   : 여러 행 선택 → 우클릭 [평가과제로 묶기]  → "평가과제" 열에 같은 이름("첫 L3 외 N건")
            또는 "평가과제" 열에 직접 같은 이름을 넣기(붙여넣기 가능)
            표 위 "평가과제 묶음" 줄에서 이름 바꾸기 · × 풀기
2) 내보내기: 행 체크(묶인 행은 묶음째) → 아래 막대 [평가과제로 내보내기]
            묶음 = Task 1개, 묶이지 않은 L3 = Task 1개씩
```

- 이미 어떤 평가 과제에 들어간 L3는 "평가 중" 배지를 붙이고, 중복으로 넣지 못하게 한다.
- 묶음은 나중에 L3를 넣고 빼거나 풀 수 있다.
- **참여자 기본값**: 연결된 L3들의 담당자를 합친 명단이다.
  - 기여도는 기존 자동 배분(균등, 피어리뷰가 있으면 그 평균)을 그대로 쓴다.
  - 화면 표기는 DATA-MODEL.md대로 "현재 배분"이다.

### 6.2 필드별 규칙 (DATA-MODEL.md 원칙 적용)

| 필드 | 누가 넣나 | 규칙 |
|---|---|---|
| `WorkItem.category` (분류) | 시트에 사람이 입력 | 시트 값을 그대로 쓴다. `과제/일반/일상`이 아니면(예: "완료" 5건, 빈칸 3건) `null`로 두고 원문은 보존한다 |
| `Task.importance` (과제등급) | L3 하나 → **그 L3의 분류를 따라감**. 묶음 → **팀장이 선택** | 묶음은 선택 전까지 `null`이다. 선택 화면에 "묶인 L3: 과제 2 · 일반 1"을 힌트로 보여 준다. 앱이 자동으로 고르지 않는다 |
| `Task.performanceGrade` (성과등급) | **팀장만** | 기본값 없이 `null`로 시작한다. 계산 규칙은 7장 질문 B |
| `Task.workload` (업무량) | — | **사용 안 함.** `criteria.workloadWeight = 0`으로 고정하고 입력칸과 기준 슬라이더를 숨긴다. 예전 데이터 값은 보존한다 |

- `editedAt`이 있어야 "시트 값"과 "앱에서 고친 값"을 구분할 수 있다.
  `isAutoDistributed`처럼 migrate에서 기본값으로 뭉개지지 않게 한다.
  없으면 "모름"으로 취급한다.
- 구현하면서 새 필드를 DATA-MODEL.md에 추가한다.

### 6.3 과제등급 3단계의 근거 (시트 「업무구분 정의」 탭, 2025-08-01)

| 구분 | 정의 | 결과물 승인 | 비고 |
|---|---|---|---|
| **과제** | 본부장이 직접 챙기는, 연말 실적 평가에 반영되는 과제 | 경영진·연구소장 | 기존 S, A 등급 기준 업무 |
| **일반** | 본부장이 챙기는 일상업무 | 연구소장·실장 | 기존 A, B 등급 기준 업무 |
| **일상** | 단순 개정·디자인 지원 | 실장·팀장 | 기존 C 등급 기준. 진척률 탭에 반영 안 함 |

## 7. 결정 사항과 남은 질문

### 확인됨 (2026-09-24)
- `F` = Finish. `완`과 같은 완료다.
- 평가 단위는 **L3 하나, 또는 L3 여러 개를 묶은 그룹**이다 → 6장·6.1
- **회사 구글 계정으로 연결할 수 있다** → 3.1의 A(Sheets API)를 기본 경로로 한다. xlsx 업로드는 대체 경로로 남긴다.
- 과제등급은 **과제 / 일반 / 일상** 3단계다. 시트의 '분류' 열과 같다.
- 성과등급은 **팀장이 입력**한다. 기본값은 없다.
- 업무량은 **당분간 쓰지 않는다.**
- 사용자 열 범위는 미정이다. **1단계는 모든 L2 공통**으로 만들고, `ColumnDef.groupId`
  자리를 비워 두어 나중에 L2 전용 열을 추가할 수 있게 한다.

### 남은 질문
- **A. 과제등급 점수.** 지금은 `중점 130 / 핵심 110 / 일반 100 / 지원 80`이다.
  새 3단계는 몇 점인가?
  - 제안: `과제 120 / 일반 100 / 일상 80`.
    일반을 기준(100)으로 두면 반영 비율 슬라이더와도 맞는다.
- **B. 성과등급 미입력 과제의 계산.** 팀장이 아직 안 매긴 과제는 어떻게 계산하나?
  - 제안: 점수 계산에서 **빼고** 결과 화면에 "성과등급 미입력 N건" 경고를 띄운다.
    모두 입력되기 전에는 **'확정'을 막는다.**
  - 임시로 B를 넣어 계산하는 방식은 팀장이 매기지 않은 등급이 결과에
    섞이므로 제안하지 않는다.
- **C. 기존 운영 데이터(main)의 과제등급 변환.** 지금 쓰는 워크스페이스에는
  `중점/핵심/일반/지원`이 저장돼 있다. 이 브랜치가 운영에 나가면 어떻게 읽나?
  - 제안: 예전 워크스페이스는 **예전 4단계 그대로** 두어 점수가 바뀌지 않게 한다.
    새로 만든 평가부터 3단계를 쓴다.
  - 자동 변환(예: 중점·핵심→과제, 지원→일상)은 지난 평가 점수를 바꾸므로
    하지 않는 쪽을 권한다.
- **D. 팀원이 L3를 입력하는 경로** (8장). 제안은 1단계 = 지금처럼 시트에 입력이다.

## 8. 사용자 권한 관리

### 8.1 현재 상태

- 백엔드가 없다.
- 계정별 localStorage와 **본인 Drive**(`drive.file`)만 쓴다.
- 역할 개념이 없다. 관리자 판별은 하드코딩된 이메일 1개와 클라이언트 비교뿐이다.
- 앱 접근 제한은 GCP OAuth 테스트 사용자 목록이 담당한다.
- → 지금 구조로는 **여러 사람이 같은 데이터를 편집할 수 없다.**

### 8.2 역할 정의

| 역할 | 할 수 있는 것 | 볼 수 없는 것 |
|---|---|---|
| 관리자 | 초대, 앱 운영 | — |
| **팀장** (워크스페이스 소유자) | L2 관리, 시트 가져오기, 모든 L3 편집, 팀원 관리, **평가·면담** | — |
| **팀원** | 본인이 담당자인 L3 추가·수정, 본인 L3의 일정 칸 | **평가 점수·등급·면담·피어리뷰 전부** |

팀원에게 가는 데이터에는 평가 데이터가 **물리적으로 들어 있으면 안 된다.**
그래서 과제 데이터와 평가 데이터는 **다른 파일에 저장**해야 한다.

### 8.3 공유 방식 후보

| 안 | 방식 | 팀원 입력 | 인프라 | 충돌 | 추천 |
|---|---|---|---|---|---|
| **A. 시트가 원본** | 팀원은 지금처럼 구글시트에 입력하고, 팀장이 앱에서 ⟳ 가져오기 | 시트에서 | 없음 | 없음 (시트가 처리) | **1단계** |
| **B. Drive 공유 폴더 + 개인 제출 파일** | 팀장이 `과제관리/{팀}` 폴더를 팀원에게 공유. 팀원은 앱에서 편집한 L3를 **자기 파일**(`제출_{이메일}.json`)에만 쓰고, 팀장 앱이 모아서 병합 | 앱에서 | 없음 (Drive 권한 = 역할) | 없음 (파일이 사람별) | **3단계** |
| C. 백엔드 (Firebase Auth + Firestore 규칙) | 실시간 공동 편집, 규칙으로 역할 강제 | 앱에서 | 필요 (비용·회사 승인) | 서버가 처리 | 보류 |

**B안에서 역할을 판별하는 방법**
- Drive 권한에서 읽는다: 폴더 소유자 = 팀장, 쓰기 권한자 = 팀원.
- 팀원 이메일 ↔ `TeamMember.email`로 "본인 L3"를 판별한다.
- `drive.file` 스코프는 앱이 만들었거나 사용자가 Picker로 연 파일만 접근한다.
  그래서 팀원은 처음 한 번 **Google Picker로 공유 폴더를 선택**한다.
- 클라이언트만으로는 역할을 **강제할 수 없다.** 팀원이 다른 사람 행을 고친
  제출 파일을 만들 수는 있다. 그래서 팀장 쪽 병합에서 **담당자가 아닌 행의
  변경은 버리고 경고**한다. 강제가 필요해지는 시점이 C안으로 넘어갈 신호다.
